# Research Forge 项目亮点与差异化定位（2026-07-19）

## 结论

Research Forge 最有价值的定位不是“又一个自动写论文工具”，而是：

> **把一个真实项目包交给系统，先判断其中的想法是否有资格扩成论文，再只生成证据允许的内容；如果失败，明确告诉用户是想法、证据、文献还是写作 Agent 出了问题。**

更适合传播的一句话是：

> **能生成论文不稀奇，敢阻止一篇不该生成的论文，才是 Research Forge。**

这不是“某个单点全球首创”的结论。GitHub 上的新项目已经覆盖端到端生成、可审计证据、失败分支、状态机和引用核验。Research Forge 真正较少被占据的是以下能力的组合：**已有项目考古 + 独立想法裁决 + 论文代理无改判权 + 阻断式论文资格门 + 失败责任定位**。

## 为什么“端到端写论文”不应当成为主卖点

截至本次检索，开源项目已大量占据“从想法到论文”的叙事：

| 项目 | 已公开的核心叙事 | 对 Research Forge 的启示 |
|---|---|---|
| [AI Scientist](https://github.com/sakanaai/ai-scientist) | 生成想法、改代码、跑实验、画图、写论文、自动评审 | “端到端”本身不再新颖 |
| [AI Scientist v2](https://github.com/sakanaai/ai-scientist-v2) | 无模板探索、树搜索、自动生成论文 | “无模板”也不能单独形成定位 |
| [CodeScientist](https://github.com/allenai/codescientist) | 以代码实验验证科研想法，多次独立尝试与汇总 | 实验闭环已有强对手 |
| [AI-Researcher](https://github.com/HKUDS/AI-Researcher) | 文献、想法、算法、实现、验证、论文全链路 | “多 Agent 科研团队”不是空白 |
| [AutoResearchClaw](https://github.com/aiming-lab/AutoResearchClaw) | 23 阶段、HITL、引用核验、沙箱实验、失败转向 | “全流程 + 防幻觉 + 失败修复”已有公开实现 |
| [XScientist](https://github.com/smileformylove/XScientist) | Git 式研究协议、探索 DAG、失败分支、ClaimRef、质量门 | “可审计、证据绑定、失败记忆”也不能声称独有 |
| [autoresearch](https://github.com/karpathy/autoresearch) | 小而快的训练实验循环，自动保留或丢弃改动 | 简单、高吞吐的实验循环已有极强心智 |

因此，首页如果只写“端到端从想法到论文”“四阶段”“多智能体”“有引用”，会立刻落入同质化比较。

## 微信公众号叙事：市场在夸什么，也在怕什么

本次使用炒股项目中已授权的 RedFox 公众号检索接口，检索了“自动科研、科研智能体、AI 科学家、想法到论文、AI 写论文、项目生成论文、科研 Agent”等关键词。RedFox 返回原文链接、标题、公众号、发布时间和互动量；当前授权结果不包含正文，因此下面只把标题与元数据当作“市场叙事证据”，不把标题中的数字当作已核验科学结论。

公众号的高频卖点集中在：

1. **规模与速度**：如“417 小时写出 166 篇论文”的 [FARS 标题叙事](https://mp.weixin.qq.com/s?__biz=Mzg4OTEwNjMzMA==&mid=2247739770&idx=1&sn=343b9c2f51d30fe36b04feec30d6a19d#rd)。
2. **端到端和权威背书**：如“Nature：首个 End-to-End 的 AI 科学家”的 [集智俱乐部文章](https://mp.weixin.qq.com/s?__biz=MzIzMjQyNzQ5MA==&mid=2247733441&idx=1&sn=101e2469d11bc8b92198bf9ba08a60dd#rd)。
3. **全流程提效**：大量课程与产品使用“文献、基金、实验、绘图、论文全流程”措辞。
4. **项目记忆与长程运行**：如“给科研 Agent 加上项目记忆，23 小时跑完 74 轮实验循环”的 [智猩猩 AI 文章](https://mp.weixin.qq.com/s?__biz=MjM5ODExNDA2MA==&mid=2450004869&idx=1&sn=5164520abb6c5e0a2919a8bf7f13a51f#rd)。
5. **状态机和流程固化**：如“别让 Agent 每次从头想”的 [科研状态机文章](https://mp.weixin.qq.com/s?__biz=MzI0MDEyNzY0NQ==&mid=2648543150&idx=1&sn=86a82120d1efee69239f0e8a03d5661c#rd)。

同时，市场焦虑也很明显：

- “AI 写论文的局限在哪里？”的 [讨论](https://mp.weixin.qq.com/s?__biz=MzA5ODQ4OTQ0Ng==&mid=2247490308&idx=1&sn=2475808e34d800d90fd55a346fd16a2e#rd)；
- “为什么 AI 生成的论文很难发 SCI？”的 [讨论](https://mp.weixin.qq.com/s?__biz=Mzk0MTc2MTU2Ng==&mid=2247499339&idx=4&sn=580073563308c49b06ee8831d8066bb7#rd)；
- “论文工厂”和高校 AIGC 检测相关标题。

这说明 Research Forge 最应该占据的不是“更快写”，而是用户已经在焦虑、但多数工具没有正面回答的问题：**这篇东西到底应不应该写？如果写不成，到底是谁的责任？**

## 按价值排序的六个项目亮点

### 1. 把“想法是否成立”和“Agent 是否写好”拆开

这是最核心、也最符合项目原始动机的亮点。第三阶段独立产出 `idea_verdict.json`，第四阶段只判断能否形成受证据约束的稿件；写作代理不能把 `mixed`、`inconclusive` 或 `unverifiable` 改成 `supported`。

可传播文案：

> **AI 科研失败了，第一次可以分清：是想法错了，还是 Agent 写坏了。**

### 2. “拒绝生成”本身是成功结果

常见系统把“成功输出 PDF”当完成。Research Forge 把工作稿、完整论文资格、论文深度审计和发表就绪拆成独立状态。即使工作稿已经生成，只要前瞻证据、协议绑定、数值证据或冻结文献不合格，完整论文写作仍保持关闭。

可传播文案：

> **它不承诺每次给你一篇论文；它承诺不把一个没被验证的想法包装成论文。**

### 3. 从“已有项目”中考古论文，而不只接收一句题目

系统只读扫描现有项目，优先识别完整的“冻结协议 → 机器输出 → 结论报告”链；找不到完整链时，才退回文本资料模式，并把结论锁为 `unverifiable`。每一阶段实际调用的代码、文档、测试、结果和报告均被单独快照和哈希。

可传播文案：

> **不是给 AI 一个题目，而是把几年项目材料交给它，让它找出哪条结果最值得写、哪条还不能写。**

### 4. 论文 Agent 没有“改判权”

这是一个很适合演示的制度设计。Stage 4 可以组织证据、生成诊断性工作稿，但不能重写 Stage 3 的结论。它把“诚实”从提示词偏好变成代码所有的权限边界。

可传播文案：

> **论文 Agent 可以写得更清楚，但没有权力把实验失败写成实验成功。**

### 5. 不只报错，还定位“谁负责修”

`diagnostic_owner` 把阻塞归到 `idea_validation`、`evidence_packaging`、`literature_grounding` 或 `paper_writer`。更下游的发表审计还会把问题回传到发现、协议、实验或综合阶段，并生成修复表和追加式失败账本。

可传播文案：

> **不是一句“论文生成失败”，而是告诉你：回第三阶段补前瞻实验，还是回第一阶段补文献。**

### 6. 本地优先、项目材料不外泄

项目包只读；凭据、环境文件、私钥、缓存和大型构建目录被排除。可选的在线文献匹配只发送标题和摘要，不发送整篇未发表稿件。这是可信基础，但更适合作为支撑卖点，不应压过前五项。

## 炒股项目是最好的首个演示

最新冻结运行 `stock-paper-gate-v4-20260718T171343Z-8078d4d7` 已经形成一个很有说服力的“有价值的拒绝”：

- 自动从炒股项目中选中 `exit-signal-research-v1`；
- 精确绑定协议、机器结果和项目结论报告；
- 提取 16 条数值证据；
- 第三阶段判为 `mixed`，证据成熟度为 `retrospective`，`idea_validated=false`；
- 生成了证据约束的诊断性工作稿，四阶段链审计通过；
- 由于不是前瞻盲测且冻结核验文献为 0，完整论文扩写被阻止；
- 责任明确归到 `idea_validation`，下一步是冻结更窄假设并取得独立前瞻证据。

这个案例的价值不在“已经写出一篇股票论文”，而在于系统没有把回顾性混合结果、16 个数字和一份可读工作稿误包装成可发表论文。

建议演示标题：

> **我们把炒股项目扔给 AI，它写出了工作稿，但拒绝替我们撒谎。**

## 目前可用的“爆点数据”

Research Forge 自身的配对 Stage 2 研究已由受保护自动评估器估计：无门控基线的 unsupported-claim rate 为 `30.56%`，门控处理为 `8.33%`，但处理运行时间高 `65.90%`。这是非常有潜力的论文主结果，不过人工复核仍被明确标记为未完成，因此现阶段只能写成：

> **在冻结的自动评估中，证据门将不受支持主张率从 30.56% 降至 8.33%；人工验证仍在进行。**

不能写成“已证明降低 73% 幻觉”或“已达到发表标准”。

## 如果把 Research Forge 本身写成论文

最值得验证的论文问题不是“Agent 能不能自动写论文”，而是：

> **独立的论文资格门，能否减少项目到论文 Agent 的错误晋级，同时保留对真实可写项目的召回率？**

建议实验：

1. 准备跨领域真实项目包，包含支持、反驳、混合、不可验证四类结果；
2. 比较普通端到端 writer 与 Research Forge；
3. 指标使用错误晋级率、不受支持主张率、证据可追溯率、责任定位准确率、可写项目召回率和总成本；
4. 消融独立 verdict、协议—输出绑定、冻结文献门和 `diagnostic_owner`；
5. 由盲法人工专家复核自动评估结论。

一个合适的论文题目是：

> **Separating Idea Validity from Manuscript Generation Failure in Project-to-Paper Agents**

## 宣传边界

可以说：

- “把真实项目包转成可审计的论文候选，并在证据不足时阻止扩写”；
- “独立区分想法验证、证据包装、文献 grounding 和写作失败”；
- “炒股项目已真实跑通四阶段，并因回顾性混合证据被正确阻断”；
- “门控自动评估显示 unsupported claims 显著下降，人工验证待完成”。

暂时不要说：

- “全球首个自动科研系统”；
- “全球首个可审计科研 Agent”；
- “可以自动生成可发表论文”；
- “已经证明比 AI Scientist、XScientist 或 AutoResearchClaw 更可靠”；
- “炒股想法已经验证成功”。

最稳妥的竞争表达是：

> **Research Forge 不争做写得最快的 AI 科学家；它要做最清楚地知道什么时候不该写的项目到论文系统。**
