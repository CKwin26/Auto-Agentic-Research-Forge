Research Forge 现有功能与 GitHub / Skill 能力总表
更新日期：2026-08-01

一、结论摘要
========================================================================
Research Forge 已形成可运行的四阶段研究工作台，并在流程控制、检索、证据约束写作、科研绘图、部分实验 Profile 和复现检查上取得真实验收。
当前最强结论不是‘可以自动完成任意科研课题’，而是：在已支持的计算实验类型中，平台能够把方向、契约、执行、证据、判定、修复和论文保持在同一条可审计链上。
机器注册表审计：18/18 项产品能力声明有本地证据；42/42 项上游采用状态通过证据定位审计。
独立复现边界：已完成本地 clean-room replay，但没有外部独立操作者和外部签署收据，因此尚未达到 C5。

成熟度：C0 概念；C1 实现；C2 组件验证；C3 受控端到端；C4 真实案例；C5 外部独立信任域复现。

二、四阶段当前能力
========================================================================
阶段一：方向发现
  过程：只读项目扫描 → Claim/关键词 → 外部文献与趋势 → Discovery Portfolio → 负责人冻结 Scope。
  现状：可用；外部检索受项目网络策略约束。
阶段二：协议与可行性
  过程：收敛议题、假设、概念基线/处理、指标/分母、资源包和 MVP；编译并批准 Research Contract。
  现状：可用但仍是主要泛化短板；已支持三类正式 Profile。
阶段三：实验与判定
  过程：构建正式资产、隔离运行、独立评估、资格门、统计规则、Hypothesis/Study Verdict、复现与 provenance。
  现状：多个真实窄案例达到 C4；跨领域通用实验仍未达到。
阶段四：论文与审计
  过程：证据约束写作、论文图表、科学面板、数字/引用/主张审计、补证据回退、PDF 和投稿批准。
  现状：写作控制闭环可用；真人外审与期刊录用不属于自动完成项。

三、核心功能清单
========================================================================
1. 统一四阶段 Study 工作流｜已达到（C3）
   已有：双入口、Study 隔离、持久化 StepInstance/DAG、负责人 Gate、暂停/恢复/重试和阶段交接。
   边界：证明流程控制闭环，不保证任意课题都能完成科学实验。
2. 本地项目只读扫描与 Claim 发现｜已达到
   已有：扫描代码、数据、报告、Office 文档和 HDF5 元数据；排除缓存、驱动包与共享二进制目录；形成候选主张和学术化概念。
   边界：语义发现链只有显式哈希/标识绑定后才能升级为正式证据。
3. 外部检索网关｜已达到（C3）
   已有：默认离线；负责人批准后统一访问论文、GitHub、公开网页、开放全文和精确 OpenML 资源，并记录预算、幂等、查询摘要和响应哈希。
   边界：Provider 安装不等于联网已获批；机构登录与正式发布仍需用户授权。
4. PaperQA 全文证据分析｜已达到（C4，限定）
   已有：固定版本、冻结 corpus/index、EvidenceSpan、引文与哈希绑定；已有真实运行验收。
   边界：不宣称普遍优于 PaperQA；完整答案由 Research Forge 的证据约束合成层生成。
5. 阶段一 Discovery Portfolio｜已达到
   已有：把本地主张、学术关键词、外部文献/趋势信号和候选贡献统一比较，由负责人选择并冻结 Scope。
   边界：趋势与热度只能辅助选题，不能决定科学 Verdict。
6. 阶段二可行性、MVP 与 Research Contract｜部分达到（C2）
   已有：定义问题、假设、基线/实验组、指标、分母、样本原则、资源需求和最小冒烟验证；Contract Compiler 阻止占位字段进入正式实验。
   边界：三类 Profile 已覆盖，但通用跨领域契约编译仍未完成。
7. 类型化实验 Profile｜部分达到（C2）
   已有：已实现 tabular_ml_v1、benchmark_prediction_v1、existing_python_project_v1，以及有限的回归、分类、检索、问卷与投资类扩展。
   边界：未知实验类型会明确阻断，不会伪装成功。
8. OpenML 隐藏标签配对实验｜已达到（C4）
   已有：OpenML Task 39 的候选与隐藏标签隔离；基线/处理在隔离容器运行，独立 evaluator 与冻结参考实现一致。
   边界：是一个真实窄案例，不代表完整 OpenML Run/Flow 兼容，也不是外部 C5 复现。
9. 官方 AIRS RAD 实验｜已达到（C4，限定）
   已有：四个官方任务、10 个种子、40 个隔离单元使用未修改官方 evaluator 完成。
   边界：不是完整 AIRS 矩阵，也未提交排行榜。
10. 既有 Python 项目密封复现｜已达到（C4，限定）
   已有：两个非预制真实项目快照在全新离线 Docker 中重放，冻结指标与重放结果一致。
   边界：仍属于本地控制的真实案例，不是外部独立信任域。
11. Great Expectations 结构资格门｜已达到（C3）
   已有：对冻结表格资源运行哈希绑定、离线结构检查，并归一化为资源资格记录。
   边界：只能证明结构质量，不能证明标签语义、因果有效性或科学结论。
12. 独立评估、证据链与 Verdict｜部分达到
   已有：Protocol→Run→Output→Evaluation→Claim 显式绑定；确定性检查优先，NLI 只做风险告警；执行失败与科学反驳分离。
   边界：仍需更多 Profile 和第二评估器家族的真实比较。
13. W3C PROV 交换｜已达到（C3，限定）
   已有：Stage 3 的受限 PROV 投影通过外部 PySHACL 语义引擎和冻结 SHACL 规则。
   边界：不宣称覆盖全部 PROV-CONSTRAINTS，也不是 W3C 认证。
14. RO-Crate 交换｜已达到（C3，Workflow Run）
   已有：Stage 3 Workflow Run RO-Crate 0.5 连同继承的 Process Run、Workflow RO-Crate 与基础 RO-Crate 必需检查全部通过外部 CRS4 validator。
   边界：Provenance Run Profile 仍待验收；不是第三方认证。
15. 故障定位、Repair 与有界回滚｜已达到（受控）
   已有：追加式诊断、最早可预防阶段、Repair Contract、Artifact Dependency Graph、successor run 和历史 Verdict 保留。
   边界：AI 只能建议故障来源；科学修复和高成本重跑仍需负责人批准。
16. 受控 clean-room replay｜已达到（C3/RF-E1）
   已有：两个密封包在全新、离线、只读根文件系统、非 root Docker worker 中重算并比较。
   边界：没有外部 KMS/WORM 收据和独立操作者，因此不能称 C5 独立复现。
17. 公共最小复现包｜已公开发布（C4）
   已有：OpenML Task 39 隐藏标签复现包和正确阻断契约案例已公开发布，并在 GitHub-hosted runner 重放；收据具有可验证的 Sigstore/SLSA provenance。
   边界：工作流仍由同一仓库所有者控制，尚无独立科学操作者签署，因此不是 C5。
18. 证据约束论文写作｜已达到（C3）
   已有：自然学术标题、分层大纲、单段摘要、章节写作、数字/引用/Claim/结构审计、证据不足披露和 PDF 编译。
   边界：不能把缺失证据美化成结果，也不能保证特定期刊录用。
19. sci-ssci 写作约束｜部分达到
   已有：已本地适配 reader-question 章节规划、目标期刊建模和证据保持型润色。
   边界：没有嵌入上游完整 Skill runtime/corpus builder。
20. Nuwa AI 科学家面板｜部分达到（C2）
   已有：盲化 Claim 包、Feynman/Tukey/Shannon/Popper 风格角色、固定路由、veto/abstain 聚合和追加裁决队列。
   边界：缺真实模型端到端验收和专门的人类裁决 UI；不得冒充真人外审。
21. 可编辑科研图与导出｜已达到（C4）
   已有：生成、审计 .drawio，并由本地 draw.io Desktop 导出 SVG/PDF；论文流水线保留可编辑源。
   边界：next-ai-draw-io 的实时 MCP 对话编辑仍只有适配器，未完成最新端到端验收。
22. Completion Record 与签名｜部分达到
   已有：记录 Study/Contract/Run、关键哈希、readiness 三层状态和独立验证命令；支持自有 Ed25519 不可变记录。
   边界：不是第三方认证、SLSA provenance 或 Sigstore 透明日志。
