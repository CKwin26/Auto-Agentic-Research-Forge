# Research Forge 前端重构方案

> 目标：在不新增后端字段、不改变 API、路由参数和业务语义的前提下，把现有页面重组为紧凑、可恢复、可审计的研究工作台。
> 本文是实施蓝图，不包含代码实现。

## 1. 目标体验

用户进入系统后首先看到“正在研究什么、基于哪个契约版本、当前是哪次运行、需要我处理什么”，而不是产品口号。

目标风格参考 Linear、GitHub Actions 和实验管理器：

- 高信息密度、低装饰。
- 标题不超过 32 px，正文和关键元数据不低于 14 px。
- 1440×900 首屏内必须看见当前对象、状态、主要内容和主操作。
- 不使用大 Hero、渐变、插画和强阴影。
- 状态由标签、文字和图标共同表达，不只依靠颜色。
- 所有重要变化都能回答：谁/什么触发、为什么、产生什么、下一步是什么。

## 2. 目标信息架构

### 2.1 三层结构

```text
全局层
├─ 产品名 / 连接状态
├─ 项目切换 / 最近任务 / 待处理
└─ 帮助

研究上下文层（持续可见）
├─ Project
├─ Contract vN
├─ Run
└─ Verdict / Task status

工作区层
├─ Overview
├─ Candidates
├─ Contract
├─ Run
├─ Evidence
├─ Verdict
└─ Remediation
```

已有项目模式默认进入项目工作区；只有尚未选择项目时展示起点选择。想法模式可继续保留为独立入口，但不应占据已有项目工作区主导航。

### 2.2 生命周期与运行阶段分离

顶部一级导航表达生命周期对象：

```text
概览 → 候选 → 契约 → 运行 → 证据 → 判定 → 补证据
```

运行页面内部再表达四阶段：

```text
发现与收敛 → 协议与基线 → 实验与判定 → 论文与审计
```

异步任务状态独立显示：

```text
排队 / 执行中 / 请求暂停 / 已暂停 / 等待用户 / 失败 / 已完成
```

科学判定独立显示：

```text
支持 / 反驳 / 混合 / 证据不足 / 暂不可验证
```

三个维度永不使用同一枚状态徽标代替。

## 3. 应用 Shell

### 3.1 桌面布局

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ Research Forge  项目▾   待处理 2   最近任务   ● 本地引擎已连接             │
├────────────────────────────────────────────────────────────────────────────┤
│ Project: 极端赢家研究 / Contract v2 / Run: run-024 / Verdict: 证据不足     │
├──────────────┬─────────────────────────────────────────────────────────────┤
│ 概览         │ 页面标题                     状态                 主操作     │
│ 候选         ├─────────────────────────────────────────────────────────────┤
│ 契约         │                                                             │
│ 运行         │                      页面内容                               │
│ 证据         │                                                             │
│ 判定         │                                                             │
│ 补证据       │                                                             │
├──────────────┴─────────────────────────────────────────────────────────────┤
│ 可选：当前任务小型状态条 / 等待用户提示                                    │
└────────────────────────────────────────────────────────────────────────────┘
```

规则：

- 左侧导航 176–208 px，可在 1024 收为图标+短标签。
- 上下文条高度 40–48 px；所有标识可复制，长名称省略但悬停显示完整值。
- 页面标题区不超过 88 px 高。
- 主操作固定在页面标题区右侧，移动端进入底部操作条。
- 如果没有项目，上下文条变为“尚未选择项目”，导航只开放起点页。

### 3.2 不新增路由的兼容策略

保留现有 URL 契约：

- `/`：起点。
- `?task=<id>`：运行或等待处理。
- `?run=<name>`：判定/运行详情。
- `?remediation=<name>`：补证据计划。

前端内部用对象状态决定激活的工作区 tab，不要求后端新增路由。浏览器 `popstate` 必须监听并重新加载对应对象。

契约确认在现有流程内仍可使用 `?task=<inspect-id>`，但页面必须从已加载 inspection + selected track 重建；若缺失则返回候选页并提示，不得默默回首页。

## 4. 页面重构

### 4.1 起点页

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 开始研究                                                             │
│ 选择已有项目材料，或从一个研究想法开始。                             │
├───────────────────────────────┬──────────────────────────────────────┤
│ 已有项目                      │ 只有想法                             │
│ [项目路径________________]    │ [描述想法_______________________]   │
│ [选择文件夹]                  │ [可选材料路径___________________]   │
│                               │                                      │
│ 外部趋势来源                  │                                      │
│ □ Semantic Scholar            │                                      │
│ □ Crossref                    │                                      │
│ □ 微信公众号（需 RedFox）     │                                      │
│ 仅发送生成的查询词，不发送项目│                                      │
│ [扫描项目并生成候选]          │ [收敛研究问题]                       │
└───────────────────────────────┴──────────────────────────────────────┘
```

外部来源必须默认为未选或在操作前出现确认层；由于现有 API 只有布尔值，可将三个来源合并为“使用已配置的外部趋势来源”开关，并明确可能访问的服务。若保持当前 `discover_claims` 语义，前端至少不能无提示传 `true`。

### 4.2 候选选题页

改为表格/密集列表 + 右侧详情：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 候选选题（13）                                      [重新扫描]       │
├────────────────────────────────────┬─────────────────────────────────┤
│ 题目             成熟度  证据链 阻塞│ 选中候选详情                    │
│ ● 极端赢家退出…  回顾性  完整   1  │ 研究问题                        │
│ ○ 排序器 V2…     原型    缺失   3  │ 为什么推荐                      │
│ ○ ……                              │ 已有材料 / 缺口 / 预计工作       │
│                                    │                                 │
│                                    │ [选择该候选并起草契约]           │
└────────────────────────────────────┴─────────────────────────────────┘
```

交互：

- 单选必须用 radio 语义或 `aria-pressed`。
- 支持按推荐、成熟度、证据链完整度、阻塞数量排序。
- 只使用现有 candidate 字段；没有的数据不生成假分数。
- 推荐理由直接来自 `paperability_reasons`、blockers、artifact chain 等已有字段。

### 4.3 契约确认页

页面顶部明确：

```text
Research Contract v2 · 草稿
基于：Candidate track-03
当前冻结版本：v1
```

主体分组：

1. 研究问题与假设。
2. 样本/范围。
3. 指标、基线与门槛。
4. 协议输入、输出与哈希。
5. 证据允许范围与限制。

如果是新版本，显示字段级 diff：

```text
样本：A  → B           设计变化
指标：M1 → M2          设计变化
输出路径：x → y        执行配置
```

只渲染后端已有值；不能比较时标明“当前接口未返回可比较值”，不能猜测。

底部确认区：

- 复选：“我确认本次运行只按该契约执行。”
- 主按钮：“冻结 v2 并创建运行”。
- 次按钮：“返回候选”。

### 4.4 运行页

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Run run-024      执行中                         [请求安全暂停]        │
│ Contract v2 · 第 1 次尝试 · 23:10 更新                              │
├──────────────────────────────────────┬───────────────────────────────┤
│ 当前工作                             │ 运行阶段                      │
│ 正在校验实验清单与数据路径           │ 01 完成                       │
│ 为什么：运行前必须绑定冻结协议       │ 02 执行中                     │
│ 预期产物：preflight-report.json      │ 03 未开始                     │
│ 下一步：执行已声明实验命令           │ 04 未开始                     │
├──────────────────────────────────────┴───────────────────────────────┤
│ 审计事件                                                             │
│ 23:10 ✓ 协议哈希验证完成  [查看产物]                                 │
│ 23:09 • 正在检查数据集路径                                           │
└──────────────────────────────────────────────────────────────────────┘
```

规则：

- 不显示模型内部推理或“思考中”；只显示事件中的 title/detail/reason/output/next。
- 不显示虚假百分比；允许阶段状态和已完成事件数量。
- “请求安全暂停”后显示 `pause_requested`，解释“将在安全检查点暂停”。
- 首个事件尚未到达时显示“正在初始化运行”，不得默认显示第 4 阶段。

### 4.5 等待用户处理页

把 requirement 放进运行页的阻断面板，而不是完全替换运行上下文：

```text
Run run-024 · 等待用户
缺少：实验清单文件
原因：自动实验只允许运行冻结协议或明确清单中的命令

[选择 manifest 文件]
校验状态：尚未校验 / 通过 / 不通过：原因

将发送到外部：无
是否改变契约：否

[验证并恢复运行]  [返回契约创建新版本]
```

错误任务单独显示失败面板：

- error 原因。
- 是否可重试。
- 最近成功检查点。
- “重试”或“查看审计日志”。

不得用合成 requirement 替代真实失败。

### 4.6 证据页

用人类可读的 Evidence Viewer 替代 JSON 抽屉：

```text
证据 / 产物
筛选：[阶段] [类型] [支持关系]

evidence-07  数值结果
结论：……
关键数值：……
来源运行：run-024
绑定协议：sha256…
产物路径：… [打开]
限制：……
```

原始 JSON 保留为“查看原始记录”的次级折叠项。证据抽屉应实现标准 dialog 行为。

### 4.7 判定页

```text
科学判定：证据不足
Run run-024 · Contract v2 · 2026-07-23

想法门      证据门      文献门
通过        未通过      未通过

结论
……

未通过原因
1. 缺少前瞻性盲测
2. 文献交叉验证不足

[生成补证据计划]   [结束并归档]
```

路由规则：

- supported / refuted → 论文资格审查。
- mixed / inconclusive / unverifiable → 补证据计划为主操作。
- “结束并归档”始终是次级出口。
- refuted 使用“反驳”而不是“未获支持/尚未验证成功”。

### 4.8 补证据计划

```text
补证据计划 v2 · 来源 run-024
3 个缺口 / 5 个建议动作 / 已选 2 个

☑ 前瞻性盲测
  缺口：……
  方法：……
  预期产物：……
  优先级：高  成本：中
  依赖：dataset-01
  所需输入：实验清单
  执行：可自动
  契约：沿用 v2

☐ 更换主指标
  …
  契约：创建 v3

执行摘要
沿用契约 1 项 / 创建新版本 1 项 / 需要用户输入 1 项
[确认所选任务]
```

确认分流：

- 全部不改变设计：批准 → 创建后继运行。
- 任一改变设计：批准 → 生成 vNext 草稿 → 用户确认 → 创建后继运行。
- 未选动作保持 proposed/skipped 语义，不得自动执行。
- 完成后显示 lineage：`run-024 → remediation-v2 → run-025`。

## 5. 统一状态模型

前端建立四个互不覆盖的只读派生层：

```ts
type ResearchContext = {
  project;
  contract;
  run;
  verdict;
  remediationPlan;
};

type LifecycleLocation =
  | "intake" | "candidates" | "contract"
  | "run" | "evidence" | "verdict" | "remediation";

type TaskStatus =
  | "pending" | "running" | "pause_requested" | "paused"
  | "waiting_for_user" | "failed" | "blocked" | "succeeded";

type ScientificVerdict =
  | "supported" | "refuted" | "mixed"
  | "inconclusive" | "unverifiable";
```

实现原则：

- 后端状态原样保留；只做展示映射，不重命名原值。
- `failed` 不自动推导 requirement。
- view 由 URL + 已加载对象决定，不由一个大 reducer 隐式跳转。
- 所有加载、空、失败、失联、权限不足状态显式存在。
- 当前上下文加载失败时保留已知 ID，并显示重试，不清空到首页。

优先复用：

## 8. 迁移顺序与独立 PR

### PR 1：状态语义与安全边界

- 拆分 task / lifecycle / verdict 展示映射。
- `failed` 与 requirement 分离。
- 清除运行阶段错误默认值。
- 外部趋势检索增加明确选择与说明。
- 修正 refuted 文案。

回滚：保留旧映射模块，以 feature flag 切回；不改 API。

### PR 2：App Shell 与上下文

- 新增 ResearchContextBar、左侧导航、紧凑标题区。
- 支持 URL `popstate` 与加载失败恢复。
- 不改变现有 query 参数。

回滚：Shell 组件可整体切回现有 Header + 页面容器。

### PR 3：候选比较与契约审查

- 候选列表/详情布局。
- 单选语义、排序与推荐理由。
- 契约分组、冻结提示、现有字段 diff。

回滚：保留原 CandidateCard 与 ContractReview。

### PR 4：运行、暂停与恢复

- 当前工作卡、阶段、审计事件。
- pause_requested 解释。
- requirement 校验状态与 failure 面板。
- 全局待处理入口。

回滚：组件级切换；任务 API 不变。

### PR 5：证据与科学判定

- Evidence Viewer。
- 三门、结论、限制、产物与原始记录层级。
- 标准 Drawer/Dialog 可访问性。

回滚：保留原 JSON viewer 作为开发者入口。

### PR 6：补证据与研究谱系

- 显示 dependencies / required_inputs。
- 选择摘要、契约影响分流。
- 来源运行、计划版本、后继运行 lineage。

回滚：保留原审批请求体，只有呈现层变化。

### PR 7：视觉 Token、响应式与自动化测试

- 应用紧凑 Token。
- 1024/1280/1440 布局。
- 键盘、对比度、焦点和截图回归。
- 修正 `lang` 与页面标题。

回滚：Token 文件单独提交，便于回退。

## 9. 风险与控制

| 风险 | 控制 |
|---|---|
| 前端把缺失对象误当成新对象 | 只展示后端返回字段；缺失即明确标注 |
| 新 Shell 破坏现有深链 | 保留 query 参数，增加 popstate 回归测试 |
| 契约 diff 看似完整但数据不足 | 只比较双方都存在的字段；不猜测 |
| 外部来源开关与单一布尔 API 不匹配 | UI 先采用总开关，不伪装成可逐源控制 |
| 补证据勾选改变请求体 | 保持现有 selected action IDs 和 approve API |
| 紧凑布局降低可读性 | 正文最小 14 px、触控目标最小 40×40 |
| 大文件拆分引入回归 | 先无视觉地抽组件，再逐页替换 |

## 10. 非目标

- 不新增后端字段或端点。
- 不改变任务、判定、契约和补证据状态语义。
- 不自动执行未确认的实验。
- 不展示内部思维链。
- 不声称不存在的项目、证据、百分比、置信度或实验产物。
- 不在本轮实现视觉和业务代码。
